How to run every session

Five questions

  1. What problem does this solve?
  2. What is the mathematical intuition?
  3. How does it actually work?
  4. When should I use it?
  5. What can go wrong?

Sixth question: did it help?

After every implementation, ask: Did this actually improve the relevant validation result? Keep the comparison against a baseline.

Notebook layout

  • 01_problem_statement
  • 02_data_loading
  • 03_data_audit
  • 04_experiment
  • 05_evaluation
  • 06_results
  • 07_conclusion

Daily schedule

  • 3:00–5:30 PM: study / understand
  • 7:00–8:30 PM: notebook / implementation
  • 10:30–11:20 PM: Excalidraw + walkthrough + optional one-take recording
  • Heavy sessions may use the next day's block; don't rush a concept to protect the calendar.

Three running datasets

  • A — regression: EDA, preprocessing, linear models, trees, boosting, deployment
  • B — classification: logistic, KNN, NB, SVM, forests, boosting, calibration, imbalance, thresholds
  • C — unsupervised: K-Means, DBSCAN, GMM, PCA, anomaly detection
  • Small external datasets only when a concept needs a different data shape.

Core rule

If it learns from data, it belongs inside the training/CV process. This applies to imputation, scaling, encoding, target encoding, feature selection, PCA, SMOTE and model fitting.

What was refined

  • Original 60 topics retained, but overloaded sessions split into focused sessions.
  • Regression diagnostics separated from the heaviest metric load.
  • Calibration/thresholds and hyperparameter optimization expanded.
  • XGBoost internals and library comparison given room.
  • Unsupervised topics separated before production.
  • Production split into pipeline, API, Docker/MLflow and monitoring.
  • PSI treated as a monitoring method, not a fourth drift type.
  • Data-quality monitoring and label-delay considerations added.

Excluded

  • Neural networks and deep learning
  • CNNs, RNNs, LSTMs, Transformers
  • Computer vision
  • LLMs, NLP modeling, generative AI

After day 66

Given a messy CSV, the learner should be able to frame the prediction problem, choose a valid split, audit and clean the data, engineer and select features without leakage, establish a baseline, choose and tune models, validate with the right metric, diagnose failure, interpret and calibrate predictions, then package the system, expose /predict, containerize it, track versions and monitor degradation.

Refined from the original 60-session plan; the extra six sessions are used only where the original scope was unusually dense.
